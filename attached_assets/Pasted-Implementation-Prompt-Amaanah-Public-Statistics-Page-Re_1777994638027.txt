Implementation Prompt: Amaanah Public Statistics Page — Rebuild & Compliance
Context
The file artifacts/amaanah-portal/src/pages/public-statistics.tsx (1 145 lines) and artifacts/api-server/src/routes/publicStats.ts contain the existing public statistics page and its backend endpoint. The page works but needs a significant visual upgrade and must be brought into strict compliance with the public/gated data boundary defined below.

The Boundary Rule (enforce this throughout)
PUBLIC — no login, freely displayed:

Total enrolled students (nationwide) with gender split and GPI
Total schools registered and active
Total teaching staff (count + gender ratio)
Number of regions and clusters covered
School type breakdown (primary, secondary, madrassa, etc.)
Overall national QA compliance rate (e.g. "74% compliant")
% of schools inspected this academic year
Compliance distribution: Fully / Partially / Non-compliant as percentages and counts — national totals only
National trend direction: Improving / Stable / Declining — a single word/icon, no per-term data
Current academic year name
Disability inclusion aggregate % (no school identifiers)
GATED — shown as a locked teaser card that leads to the "Request Data Access" modal:

Regional or cluster compliance breakdowns
School-level QA scores or rankings
Per-term or per-inspection detail
Infrastructure data
Exam results
Individual teacher/student records
Attendance data
The current code violates the boundary in one place: qaCompliance.byRegion is returned by the API and rendered as a public table. This must be moved behind the gated wall.

Backend changes (publicStats.ts)
Remove qaCompliance.byRegion from the public response — do not return it at all from GET /api/public/statistics. Remove it from the SQL query too.

Add currentAcademicYear to the response: the year whose status = 'active', or if none, the most recently started year. Return { id, name, startDate }.

Add totalClusters to the summary: count of cluster rows in the DB.

Add qaCompliance.trend — a single string: "improving" | "stable" | "declining". Compute it by comparing the average compliance of the two most recent academic years that have finalized inspections. If only one year has data, return "stable". No per-year scores exposed — just the direction string.

Add qaCompliance.inspectedThisYear — count of schools inspected in the current academic year (the year identified in step 2), not all time. Add coveragePctThisYear accordingly.

Frontend redesign (public-statistics.tsx)
Completely redesign the page visually. Keep all existing logic; replace the layout and styling. Use only React, Recharts, Tailwind, and lucide-react (already installed). Do not add new packages.

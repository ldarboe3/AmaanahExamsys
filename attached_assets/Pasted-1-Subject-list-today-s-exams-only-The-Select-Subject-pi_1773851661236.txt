1. Subject list — today's exams only
The "Select Subject" picker now fetches live exam schedules from the server and shows only subjects scheduled for today's date. Each subject row shows:
•	The exam name
•	Its status: ● In Progress (amber), ✓ Completed (green), or Starts HH:MM (grey for upcoming)
If no exams are scheduled for the day, the picker shows a clear message: "No exams scheduled today — Contact HQ if you believe this is incorrect." — preventing any accidental recording against a wrong or non-existent exam. The list refreshes automatically every 5 minutes.
2. Index Number — scan-only, non-editable
The index number field is now a read-only display:
•	Shows "Scan exam card to fill automatically" with a padlock hint until a card is scanned
•	The value populates automatically when the barcode is read by the camera
•	An ✕ button appears to clear and re-scan if needed
•	Cannot be typed into — eliminating manual entry errors
3. Confirmation banner — larger and clearer
After each scan, a full-width banner appears with:
•	A large icon in a circular badge (32pt, in a frosted white circle)
•	Bold headline: Attendance Recorded / Already Recorded / Student Not Found / Saved Offline
•	The student's full name (when found) on a separate line
•	Index number + subject in the sub-line
•	Stays visible for 6 seconds (up from 4)

ExamSys integration prompt for today's subjects:
The attendance screen currently reads today's exam schedule from the local API proxy (which falls back to demo data). To connect directly to ExamSys as the source of truth for which subjects are scheduled:
GET /api/public/exam-schedules?examDate=YYYY-MM-DD
The app calls this with today's date. Expected response (already supported by the proxy):
[
  {
    "id": 1,
    "subject": "Mathematics",
    "examDate": "2026-03-12",
    "scheduledStartTime": "08:00",
    "durationMinutes": 150,
    "status": "in_progress"
  }
]
The status field should be one of upcoming, in_progress, or completed — the app uses this to colour-code each subject in the picker. If ExamSys already has GET /api/public/exam-schedules, the proxy is already forwarding to it, so no app changes are needed — just ensure the endpoint returns the status field.
